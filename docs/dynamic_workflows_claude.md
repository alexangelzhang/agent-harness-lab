# 每项任务都有一个 harness：Claude Code 中的动态工作流

来源：https://zhuanlan.zhihu.com/p/2097582147485824443（原文 claude.dev，作者 Thariq Shihipar 和 Sid Bidasaria，2026-06-02）

## 什么是动态工作流

Claude Code 现在可以即时编写并编排自己的多智能体 harness。默认的 Claude Code harness 为编程构建，但面对运行时间长、高度并行、结构复杂或对抗性强的任务会失效——工作流让 Claude 动态创建构建在其上的 harness，并可为每项任务定制，还可以分享复用。

动态工作流会执行一个 JavaScript 文件，其中包含特殊函数：`agent()` 生成子智能体；`parallel()` 和 `pipeline()` 用于组合多个子智能体。还能决定每个智能体用什么模型、是否在自己的工作树中运行（选择所需的智能水平和隔离程度）。工作流被中断后，恢复会话可从中断处继续。

## 为什么要用：单上下文窗口的三种失效模式

1. **智能体懈怠**：完成复杂多部分任务之前停下来，只取得部分进展就宣称完成（如 50 项安全审查只处理 35 项）。
2. **自我偏好偏差**：偏爱自己的结果，尤其在要求它按评分标准验证自己的产出时。
3. **目标漂移**：多轮交互中逐渐偏离最初目标，尤其是上下文压缩之后——摘要损失信息，边缘情况和「不要做 X」这类约束可能丢失。

工作流用多个各自拥有独立上下文窗口、目标聚焦且彼此隔离的子智能体来应对。

## 动态 vs 静态

静态工作流（Agent SDK / claude -p 编排多个实例）必须适用于所有边缘情况，所以通常比较通用；动态工作流由 Claude 根据眼前的具体任务量身编写 harness。

## 六种模式

1. **分类并执行**：分类器智能体判断任务类型，分派给不同智能体或采用不同行为；也可在末尾用分类器确定输出。
2. **扇出并综合**：任务拆成许多小步骤各由一个智能体处理，然后综合。步骤多、或每个步骤能从独立干净上下文受益（避免互相干扰/交叉污染）时尤其有用。综合步骤是屏障：等所有扇出完成后把结构化输出合并。
3. **对抗式验证**：对每个生成的智能体，再运行一个单独生成的智能体，依据评分标准或准则对其输出做对抗式验证。
4. **生成并筛选**：生成多个想法，按评分标准筛选/验证，去重，只返回质量最高且经过测试的。
5. **锦标赛**：不拆任务，让智能体相互竞争——生成 N 个智能体用不同方法做同一任务，由提示词/模型两两对比评判，评审智能体持续评判直到选出胜者。每次比较用全新智能体，没有单个上下文需要容纳全部项目；比较式判断比绝对评分可靠。
6. **循环直到完成**：工作量未知的任务，持续循环生成智能体直到满足停止条件（没有新发现、日志不再报错），不预设固定轮数。

## 使用场景

- **迁移和重构**：把任务拆成调用点、失败测试、模块等步骤，每个修复在工作树里生成子智能体完成，另一个对抗式审查，然后合并。可提示不要用资源密集型命令以尽量并行。
- **深度研究**（/deep-research）：扇出搜索、抓取来源、对来源声明做对抗式验证、综合成带引用的报告。
- **深度核验**：一个智能体识别所有事实声明，每项声明一个子智能体核查，每个核查后还可再跟来源质量审查。每项事实声明都对应一个核查智能体。
- **排序**：锦标赛——两两比较的流水线，确定性循环保存对阵表，上下文只保留当前顺序；或并行分桶排序再合并。
- **记忆和规则遵循**：规则逐条审查——每条规则由干净上下文中的核验器负责，再由质疑者筛查误报。反向做法：从会话和评审评论中聚类出反复纠正的意见，对每条候选规则做对抗式验证（能否避免一个真实错误？），通过验证的提炼回 CLAUDE.md。
- **根因调查**：让智能体基于互不重叠的证据（日志、文件、数据各一个）提出假设，防止自我偏好偏差；每个假设交核验者和反驳者审查。也适用于销售复盘、数据工程。
- **大规模分流**：每个条目分类、与已有事项去重、采取行动（修复或升级人工）。**隔离模式**：读取不可信公开内容的智能体禁止执行高权限操作，由负责行动的智能体根据摘要执行。
- **探索和品味**：设计、命名等依赖品味的任务——探索一系列方案，给评审智能体一套标准，达标即完成。
- **评测**：工作树中生成独立智能体 + 比较智能体，按评分标准打分具体输出。
- **模型路由**：分类器智能体先研究任务复杂度（如 auth 模块多少文件），再分派给 Sonnet 或 Opus。

## 何时不该用

工作流会用更多 token，最适合复杂且价值高的任务。常规编程任务大多不需要五位评审团；多智能体 vs 单智能体的选择同理——并行化和专业化必须值得协调成本。

## 实用技巧

- 详细提示，用上述具体技巧；工作流也适用于小任务（「快速工作流」，如快速对抗式审查某个假设）。
- 与 /goal（硬性完成要求）和 /loop（定期运行分流/研究/核验）结合。
- 可设明确 token 预算（如「使用 10k token」）。
- 按 s 保存工作流到 ~/.claude/workflows；也可放进技能文件夹在 SKILL.md 中引用分享——提示 Claude 把技能里的工作流当模板而非必须原样运行的脚本。
