# Harness 中的上下文管理：从输入优化到系统自进化

来源：https://zhuanlan.zhihu.com/p/2096250258795787441

## 1. 我们为什么要优化上下文？

LLM 的输入是一段可以任意编辑的语言，语言的表达力极强，但也很容易被冗余、歧义、位置和来源混淆所干扰。

观点1：LLM 是语言模型，它对任务的认知都来自输入。所以研究 agent 的上下文管理，本质上是在研究怎样优化语言模型的输入。

上下文管理优化的是状态 s_t，模型做的是 f(s_t)→a_t 的映射。

观点2：一个 s_t 好不好，取决于读它的那个 f，因此不存在对所有模型都有效的上下文策略。

## 2. 上下文管理包含哪些内容？

除 system prompt、user input、环境状态（observation）、过往历史等常见的从外部环境获取和观测到的内容外，还包含着两类特殊的上下文：记忆与知识库。

记忆是上下文的重新组织：它源于上下文，又回到上下文中。无论是任务内的 working memory，还是跨任务的 episodic memory，都是把历史按另一种结构重新排列。除了显式文本，记忆还可以是隐式状态或模型参数。

知识库与 skill 则是把 prior knowledge 注入上下文。

一次模型调用可以写成条件生成：y_t ~ p_θ(·|c_t)。参数一旦固定，模型能做的就只剩一件事：读 c_t，给出输出。系统指令、先验知识、历史轨迹、当前观察、工具定义，所有信息都被压进同一条 token 序列，通过 attention 相互作用。

## 3. 上下文管理的目标

长程 agent 任务可以拆为两个相互耦合的阶段：

- a_t ~ f_θ(·|s_t)：模型如何使用输入（agent 优化）
- s_{t+1} = Update_φ(s_t, a_t, e_t)：系统让模型看见什么（上下文优化）

f_θ 是训练所优化的映射；Update_φ 是上下文管理策略：把已有上下文、模型的动作和环境变化汇总成下一步的输入。

要分清两个状态：x_t 是客观世界，s_t 是 agent 对世界的主观表示。上下文管理直接优化的是 s_t，以及用来构造未来 s_t 的记忆；它通过改变模型的动作，间接影响环境。

约束条件：

| 约束 | 具体问题 |
|---|---|
| 容量 | 历史、工具结果和输出预留放不进同一个窗口 |
| 信息利用 | 证据被噪声、位置或冲突信息掩盖 |
| 成本与时延 | 每轮都要重复处理历史，压缩本身也要花钱 |
| 状态一致性 | 旧结论已失效、执行结果未验证、文件已改动 |

从接口上看，上下文管理是输入优化；从整个系统看，它是一种控制「未来能用上哪些信息、以什么代价获取信息」的策略。

## 4. 不同预算对应不同能力边界和上下文策略

上下文管理的目标不是塞进尽可能多的信息，也不是一味压缩 token，而是在预算约束下让后续决策更好。

1. 沿着同一条曲线看，是预算与效果的权衡。放宽上下文、推理深度和交互轮次，成功率会上升，但边际收益递减，成本成倍增加。线上服务要在 low / mid / high 之间找性价比的拐点，前沿探索则用 max 去摸模型的能力上界。
2. 在不同曲线之间看，是帕累托前沿的移动。同一个 harness 下单纯加预算只能沿着曲线往右走；想让整条曲线往左上方移动——花更少的钱、做对更多的题——要靠模型本身更会理解状态、更少做无效探索，也就是优化 f(s_t)→a_t。

## 5. 可参考的部分成熟上下文管理策略

| 路径 | 主要解决的问题 | 代价 |
|---|---|---|
| 输出约束、分页、程序筛选 | 大型工具结果、重复日志 | 入口筛掉的信息后面可能用得上 |
| 近期窗口、observation masking | 低成本抑制历史膨胀 | 长期依赖需要另外保存或回读 |
| 结构化状态、summary / folding | 任务连续性、工作集大小 | 失真、过早概括、摘要逐层漂移 |
| 外部存储、检索与精确回读 | 超出窗口的信息、细节恢复 | 需要发现入口，读取也有成本 |
| 信息隔离与任务分解 | 执行细节干扰规划 | 交接损失、协调成本 |
| 稳定前缀、批量替换 | 重复输入带来的成本和时延 | 长度最优和缓存最优可能冲突 |
| 学习型管理器 / 读取器、联合训练 | 手工规则与模型能力不匹配 | 训练成本、分布迁移、信用分配 |
| 跨任务经验、skill 与参数更新 | 重复犯错、知识无法复用 | 负迁移、经验过期、验证成本 |

## 6. 上下文管理的挑战

没有办法对真实环境的状态做完整建模 x_t→c_t。真实环境复杂度很高，只能凭经验预估信息量相对更高的部分构造为上下文。

如何基于已有状态迭代上下文、如何取舍？设 C_φ(h_t) 是历史的压缩表示，定义决策失真 D_θ(h_t, C_φ(h_t)) = V_ref(h_t) - V^{f_θ∘C_φ}(h_t)。如果参照是「同一个模型读完整历史」，这个差值甚至可能为负——删掉噪声，决策反而更好。目标写成 min_φ E[D_θ + λ·Cost(C_φ, h_t)]。任意上下文的构造都依赖某个具体的模型 θ，很难存在同时满足不同模型的策略——这就是为什么要对不同模型构建不同 harness。

## 7. 为什么没有对所有模型都有效的上下文管理？

既然最优的 s_t 取决于 f_θ，手工调 φ 就永远在追一个移动的靶子。更根本的做法是让两者一起适应：先让模型学会读压缩后的状态，再进一步让模型自己决定怎么管理上下文，把 Update_φ 的一部分并入 f_θ 的训练。背后的机制是输入分布的偏移：每个模型训练见过的轨迹分布都不一样，手工压缩对一个模型是去噪，对另一个可能是从没见过的输入。

## 8. 训练中学习上下文管理

- 阶段一：学会读压缩后的状态（如 ReSum——会读原始历史不代表会读摘要，需要 RL 适配压缩状态分布）。
- 阶段二：让上下文管理成为模型的动作（AgentFold 把 folding 内化为输出动作；Memory-R1 用下游任务奖励监督记忆增删改查）。
- 阶段三：在隐空间里学习状态（AutoCompressors / Mem1：状态表示与读取在连续隐空间联合适应）。

## 9. 内循环与外循环

| 维度 | 内循环：in-task（agent 优化） | 外循环：cross-task（system 优化） |
|---|---|---|
| 目标 | 在当前约束和预算内完成任务 | 提升未来一系列任务上的质量、成本和可靠性 |
| 更新什么 | 当前计划、证据、工作上下文、任务记忆 | 长期经验、skill、检索器、管理策略、harness 代码、模型参数 |
| 反馈来源 | 工具观察、测试结果、当前任务的验收 | 多条轨迹、失败归类、独立评测、用户纠正 |
| 典型风险 | 忘记约束、重复探索、误判完成 | 过拟合历史任务、负迁移、经验过期、评测泄漏 |

in-task 循环依赖 agent 本身对上下文的能力与世界知识；cross-task 循环更多考虑经验间的复用、工程的迭代。两个循环通过记忆连在一起：内循环的记录是外循环学习的原料，外循环产出的经验和 skill 又成为下一次内循环的先验。当系统工程从 in-task 优化逐步开放到 cross-task 优化时，就诞生了记忆、知识库、harness 工程以及 RSI 等工作。
